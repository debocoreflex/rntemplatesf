# `databaseLayer` — Repository Pattern for Data Abstraction

This layer implements a **generic and decoupled repository architecture** using TypeScript, enabling clean separation between your application logic (e.g., ViewModels) and database-specific implementations like **SmartStore**, **Realm**, or **Firestore**.

---

## Purpose

* Abstract all database operations (save, update, query, delete) behind a **common interface**.
* Keep ViewModel and UI logic **agnostic of the underlying database**.
* Support future plug-and-play migrations between databases (e.g., SmartStore → Realm) with minimal changes.

---

## 📁 Folder Structure

```text
src/
└── databaseLayer/
    ├── entities/
    │   └── CommonEntity.ts             ← Domain-level object used across ViewModel and Repository.
    │
    ├── interfaces/
    │   ├── CommonInterfaces.ts         ← Generic interfaces: IRead<T>, IWrite<T>, IQuery<T> 
    │   └── queries/
    │       └── GenericQueryParams.ts   ← Generic query input DTO for ViewModel to Repository
    │
    └── repositories/
        ├── BaseRepository.ts           ← Abstract base class implementing common DB operations.
        └── specificrepositories/
            └── ContactRepository.ts    ← Entity-specific repository (Contact), extends BaseRepository
```

---

## 🔄 Flow: How ViewModel Talks to Database

```text
ViewModel → FeatureRepository (implements BaseRepository) → DatabaseUtills (smartstore or Realm etc.)
```

### Example: Save Flow

```ts
// ViewModel
const contactEntity = new CommonEntity(...);
contactRepo.save(contactEntity); // ← ViewModel has no idea what DB is used
```

### Example: Query Flow 

```ts
// ViewModel
const queryParams = {
  entityType: 'Contact',
  fields: ['Id', 'Name', 'BillingCountry'],
  filters: [{ field: 'Id', operator: '=', value: '001xx000003DGXo' }],
  limit: 10
};
contactRepo.query(queryParams); // BaseRepository handles the translation to SmartSQL
```

## 🧩 Components Explained

### ✅ `entities/CommonEntity.ts`

A generic entity class representing a domain object like `Contact`, passed between ViewModel and repository. Keeps ViewModel decoupled from DB-specific schema like SmartStore's `__local__`, `attributes`, etc.

---

### ✅ `interfaces/CommonInterfaces.ts`

Defines three core interfaces:

* `IWrite<T>` – for save, update, delete.
* `IRead<T>` – for get and getAll.
* `IQuery<T>` – for generic querying using `GenericQueryParams`.

---

### ✅ `interfaces/queries/GenericQueryParams.ts`

A standard DTO used to define any query from the ViewModel:

```ts
{
  entityType: 'Contact',
  fields: ['Id', 'Name'],
  filters: [{ field: 'Department', operator: '=', value: 'Engineering' }],
  limit: 10
}
```

This allows the `BaseRepository` to convert it into a DB-specific query (like SmartSQL or Realm filters).

---

### ✅ `repositories/BaseRepository.ts`

An abstract class that:

* Implements all generic methods: `save`, `query`, etc.
* Translates high-level generic queries into database-specific logic (e.g., SmartStore).
* Adds DB-specific metadata like `__locally_created__`, `attributes`, etc., so ViewModel stays clean.

---

### ✅ `repositories/specificrepositories/ContactRepository.ts`

Extends `BaseRepository<CommonEntity>` and can override or extend logic specifically for `Contact`.

---

## 💡 Benefits

* 🧼 ViewModels are **clean, dumb, and testable**.
* 🧱 Database can be **swapped or changed without touching the app logic**.
* 🪝 Domain models (`CommonEntity`) are consistent throughout the app.
* 🔍 Query logic is reusable and supports smart translation via `GenericQueryParams`.
